# 모션 — 상태 변화를 설명하는 전환만 둔다

## 지금의 결정

적용된 모션과 방식:

- **상태의 색 전환** — 호버·눌림·선택에서 배경·테두리·글자색을 전환한다.
- **접기/펼치기의 크기 전환** — 사이드바는 폭, 최근 파일 목록·트리 하위는 grid 행 높이를 전환한다.
- **접기 셰브론 회전** — 펼침 상태에서 90° 회전한다.
- **다이얼로그 진입·퇴장** — `dialogIn`·`dialogOut` 키프레임. 값은 `packages/ui/src/panda-preset.ts`가 소유한다.

공통 규칙:

- 지속시간·이징은 토큰 `fast`·`out`만 쓴다.
- **모든 모션은 `_motionReduce`로 끈다** — OS의 "동작 줄이기"에서는 전환 없이 즉시 상태를 보인다. 누락을 잡는 자동 검사는 없다 — 추가할 때 직접 확인한다.
- 상호작용이 트리거일 때만 돈다 — 시간·스크롤에 반응해 스스로 도는 모션은 없다(idle 비용 0).
- 흐림(backdrop-filter)·그림자는 전환하지 않는다(→ [작업 규칙 · 성능](../../../rules/project-rules.md#성능-규칙)).

## 예외 — 그대로 구현하면 깨지는 지점

- **접기/펼치기는 언마운트하지 않는다.** 언마운트하면 전환할 요소가 사라지고, 다시 펼칠 때 트리·목록 상태가 초기화된다. 크기를 0으로 두고 `visibility: hidden`·`aria-hidden`으로 포커스·스크린리더에서 뺀다. 다이얼로그 퇴장도 같다 — 전환이 끝난 뒤 `close()`와 언마운트를 한다.
- **안쪽 여백은 접힘과 함께 0으로 전환한다** — 여백은 상자의 최소 높이로 남아, 두면 접힌 뒤에도 그만큼 빈 자리가 남는다.
- **lazy로 읽힌 하위의 첫 펼침은 접힘으로 붙인 뒤 타이머로 펼친다** — 마운트와 펼침이 같은 프레임이면 전환이 시작점 없이 끝 상태로 그려진다. `requestAnimationFrame`이 아니라 타이머인 이유는 [테스트 전략 — 성숙도 주의](../../testing.md#성숙도-주의)가 소유한다.
